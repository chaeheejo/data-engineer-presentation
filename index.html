⚡ 연계 기술 비교

데이터 추출 방식: 기존 방식 vs CDC (Change Data Capture)

원천 데이터베이스에 부담을 주지 않고 실시간으로 데이터 변화를 감지하는 방법

기존 방식 (Query-based Polling)

높은 자원 사용
[원천 DB] SELECT * FROM ... (전체 조회) [Data Lake]
  • • 주기적으로 전체 데이터를 반복해서 쿼리(Query)로 조회하여 가져옴
  • • 데이터량이 커질수록 원천 DB의 CPU/메모리 부하 증가

CDC 방식 (Log-based Push)

저리소스 / 고효율
[Transaction Log] [INSERT/UPDATE] 변경 건만 감지 [Data Lake]
  • • DB 내부 트랜잭션 변경 로그만 감지하여 변경된 데이터만 즉시 전송
  • • 원천 DB에 조회를 날리지 않아 시스템 성능 영향을 최소화

💡 CDC 방식을 사용하면, 24시간 끊임없이 작동하는 제조 DB의 서비스 영향 없이 안전하게 실시간 데이터를 수집할 수 있습니다.

🛠️ 실제 현업 업무

데이터 파이프라인 관리 & 트러블슈팅

초당 수십만 건 발생하는 반도체 생산 데이터를 장애 없이 흐르도록 유지하는 역할

주로 발생하는 이슈 및 현장의 질문

  • Q. "대시보드에 특정 시점 데이터가 비어있어요!" 데이터 연계 과정에서 네트워크 또는 스키마 변경 등으로 발생하는 데이터 누락(Missing Data) 문의 대응
  • Q. "실시간 데이터 반영이 수 분 이상 늦어집니다." 대용량 처리 병목 현상으로 인한 연계 지연(Latency/Lag) 발생 원인 분석

삼성전자 데이터 엔지니어가 하는 일

  • 파이프라인 흐름 모니터링: 원천 DB부터 Data Lake까지 데이터 유실 없이 정상 도달하는지 감시
  • 장애 원인 추적 & 복구: 연계 테이블 트러블 발생 시 병목 구간을 찾아 보정 및 재전송 조치
  • 안정적인 흐름 보장: 공정 엔지니어들이 원하는 데이터에 언제든 즉시 접근할 수 있도록 인프라 지킴이 역할

🐋 「아기 고래의 첫 항해」 문제 상세 내용
1. 격자 지도 & 장애물

$N \times N$ 바다 격자 상에 아기 고래, 먹이, 그리고 통과 불가능한 암초(1)가 존재합니다.

2. 방향 및 이동 규칙

고래는 바라보는 방향(상/하/좌/우)으로 직진하며, 암초를 만나면 시계 방향 90도 회전하여 탐색합니다.

3. 성장 및 먹이 메커니즘

자신의 크기 이하인 먹이만 먹을 수 있으며, 크기만큼 먹이를 먹을 때마다 고래 덩치가 1씩 성장합니다.

4. 최단거리 탐색 (BFS)

먹이가 여럿일 경우 가장 가까운 거리 $\rightarrow$ 가장 위쪽 $\rightarrow$ 가장 왼쪽 먹이를 우선 방문합니다.

💡 엔지니어의 평가 포인트: 2차원 배열 제어 능력 + BFS 최단거리 탐색 알고리즘 + 빡빡한 시뮬레이션 예외 처리를 정확하게 코드로 구현할 수 있는지 검증합니다.
